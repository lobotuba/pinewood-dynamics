MINIMUM VERIFICATION TEST SET FOR FIXED AXLE/WHEELBASE
V-AX-001 Baseline measurement load: load a project with known test axle datums; confirm wheelbase derivation.
V-AX-002 AI generation: generate several radically different bodies and assert identical axle datums.
V-AX-003 Manual edit: attempt move/scale operations that would relocate chassis references; assert lock enforcement/noncompliance handling.
V-AX-004 Optimizer: include geometry and ballast variables; assert axle/wheelbase variables are absent when locked.
V-AX-005 Wheel setup: change camber/toe; assert master axle datum/wheelbase values remain unchanged.
V-AX-006 Persistence: save/reload/version copy and compare datum values, units, provenance, locks.
V-AX-007 Technical inspection: deliberately corrupt a test datum in an engineering-test fixture and assert axle and wheelbase checks fail independently of published-rule checks.
V-AX-008 Export: compare master-model datum references with exported manufacturing references within declared export tolerance.
V-AX-009 Provenance: verify UI/build sheet says LOCAL/FROZEN, not RULE, for fixed wheelbase under the current source set.
V-AX-010 Gate independence: create a test geometry that fails nose contact while axle/wheelbase passes, then a separate fixture that passes nose contact while local axle lock fails.

OPEN ITEMS / EXIT CRITERIA
OPEN-AX-001 | Measure or obtain authoritative official-kit front and rear axle datum coordinates. Until then exact coordinates remain UNKNOWN.
OPEN-AX-002 | Define coordinate-system convention and datum-reference geometry before implementation freeze.
OPEN-AX-003 | Define acceptable measurement/storage/export tolerances based on the real kit and manufacturing workflow; do not invent tolerances before characterization.
OPEN-GATE-001 | Characterize the real starting pin/contact geometry. Until then only the published functional no-point/no-upward-slope rule is authoritative.

MATRIX GOVERNANCE RULE
No requirement may change provenance class because it is convenient for implementation. In particular, fixed axle locations and nominal wheelbase remain LOCAL/FROZEN until supported by an authoritative rule source. The same requirement IDs shall be used in specifications, source code/tests, validation records, and build/export checks so implementation evidence can trace back to this matrix.
